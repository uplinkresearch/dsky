A simpler page, PCs named by serial, and writes that survive a stick reset

Three changes. One reshapes the page, one replaces domain join with naming
by serial number, and one fixes a write that failed partway through.

Three keys and a Settings button

The page had five keys and fourteen panels. It now has three keys (Install,
Payload, Disks) and a Settings button for the things you set up once.
Everything it could do before is still there.

Copy a drive and Disk utility are one Disks screen: pick a disk, read its
card, then Copy it onto other disks, Erase and prepare, or Capture to an
image. Master is gone; Workspace, Your installers, Storage (what was
Downloaded) and Sources live in Settings. Each recipe and the images built
from it share one row under Saved setups with one Write to stick button,
which reuses the built image while it still matches and rebuilds it when it
does not. A stick is called a stick everywhere, the Rescan and Refresh
buttons are gone because the drive list already updates every five seconds,
and the version label is now the update check. In the Install dialog, Admin
name, Password never expires and Skip TPM checks sit under More options.

PCs are named PC-<serial>, and DSKY no longer joins domains

DSKY no longer joins a PC to a domain, by any path: the Install dialog
option, the answer file join, `dsky install --domain-blob`, and the join a
migration build provisioned are all gone. A recipe that still sets
windows.domain is refused by name, so it cannot quietly build workgroup
machines. A migration of a domain PC builds it unjoined under the plan's
name and warns up front with the domain, OU and groups for whoever joins it
by hand.

Instead, Install names the PC PC-<serial> (a tick in the Install dialog, on
by default; `dsky install --name-by-serial`). A long serial keeps its last
12 characters, and a placeholder serial falls back to the network card
address. The post-install check fails a PC whose name did not take.

A stick that resets partway through a write

A SanDisk stick failed two Windows 11 writes with "A device which does not
exist was specified", because it dropped off the bus and came back in the
same second. DSKY now waits up to a minute for the stick, finds it again by
serial number, bus and size, backs up 64 MiB and carries on more gently. A
read-back picks up where it was. A third disconnect ends the run with a
plain message to replace the stick, a stick with no serial number is never
resumed onto, and the read-back at the end still decides whether the stick
is good.
