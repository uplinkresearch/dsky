Programs install on a fresh Windows 11, and say why when they cannot

Two changes. One fixes a bench failure, the other adds an option someone asked for.

Programs install on a freshly imaged PC

On an ASUS NUC15 with a fresh Windows 11, every program failed together. The
screen said only "could not install Google.Chrome", "could not install
7zip.7zip", and so on, with nothing to say why. When every program fails at
once, the problem is winget's catalog, not the programs. The App Installer that
comes with a fresh Windows can be too old to read today's catalog until the
Store updates it, and a PC that never got online fails the same way.

The agent now checks winget's catalog before it installs anything. If the
catalog will not refresh, the agent resets it. If that fails too and the PC is
online, it installs the current App Installer from Microsoft and tries again.
If winget has not appeared after a minute, the agent asks Windows to register
it instead of only waiting. Programs now come from winget's own catalog, so a
Microsoft Store that has not updated yet cannot block them.

If programs still cannot install, the screen says so once and gives the reason:
the PC never reached the internet, or winget could not read its catalog. That
one line also lists the programs it skipped. A single program that fails now
shows winget's error in words, with the code.

"Password never expires" for the local account

A bench-built PC used to take the machine's password policy: on a standalone
Windows PC, the password expires after 42 days. The person who received the PC
was then asked for a new password six weeks later, or locked out. Image setup
now has a "Password never expires" tick under the administrator's password.
The CLI flag is --password-never-expires, and the text wizard asks too. It is
off unless ticked, and hidden for normal Windows setup, where the account
belongs to the end user.
